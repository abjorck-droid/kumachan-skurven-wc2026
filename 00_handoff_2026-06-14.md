## Fixed this session

### 1. Match stuck "Live" at 81' — scoreboard only polled one UTC day

**Symptom**: Brazil v Morocco (fixture 1489371) showed as live at 81' long after full time, even
though two later matches resolved fine.

**Root cause**: `run_scoreboard` queried only `date = utcnow().date()`. API-Football buckets each
fixture under its **kickoff's UTC date**. BRA v MAR kicked off **22:00 UTC June 13**, so it sat in
the June-13 bucket. Once UTC rolled to June 14 the poller queried June 14 only — the match dropped
out of every query mid-second-half and froze at its last Live snapshot (status Live, elapsed 81),
never recording FT. Any kickoff ~21:30–00:00 UTC (most US evening slots) crosses midnight and would
hit the same trap.

**Fix**: new pure `poll_dates(utc_today, target_date)` in `poller.py` — automated runs poll
**yesterday + today** (UTC); an explicit `--date` polls just that day (backfills). Fixtures deduped
by `fixture_id` (buckets are disjoint). Re-touching yesterday's finals is idempotent. A
boundary-crosser now self-heals on the next cycle. Tests: `tests/test_poller_scoreboard.py`.
One-time unstick was `poller.py --mode scoreboard --date 2026-06-13` → resolve → scoring.

### 2. Final-minutes goals could be lost — events frozen at last Live poll

**Root cause**: the poller fetched a fixture's events while Live, or the first time it saw it
Finished *without* stored events. Since live polls already store events, a finished match was never
re-fetched, so any goal after the last Live snapshot (cadence 15 min) was never backfilled —
undercounting Top Scorer / Golden Boot.

**Fix**: new pure `should_fetch_events(short, prev_status, has_events)` — also fetch on the
**Live→Finished transition** (prior status is read from Airtable *before* the upsert flips it).
Then it stops (no wasted calls). **Caveat**: only fixes matches from here on; already-finished
matches aren't re-fetched. All 8 played so far check out — late goals in KOR–CZE and QAT–SUI were
captured. A one-time `--refetch-events` backfill flag was offered and judged unnecessary; add it if
a past match ever looks short a late goal.

(`01_API_findings.md`) was to pull the API topscorers board into `leaderboards-poll`, but that half
was never built — the Footballers stat columns (`goals_in_tournament`, `assists_in_tournament`,
`clean_sheets_started`) sat empty. Event-derived makes the board **exactly match** how the Top
Scorer / Golden Boot side games settle (same `is_counting_goal`: own goals & missed pens excluded).

**Data flow** (all committed):

1. `resolve_sidegames.py` — each run, `goal_tallies(events)` over all stored events; new pure

   the 15-min scoreboard workflow, so the board updates live.

   so we fetch only scorers, not all ~1,250 squad players); `publicView` returns a `scorers` array
   sorted goals → assists → name. Wrapped in try/catch so a missing field can't break the feed.
3. `site/live.html` — new **Top scorers** tab (`scorersTab()`): competition ranking with shared
   places (1,2,2,4), assists as tiebreak, team flag/code via `IDX`. Demo data added for `?demo=1`.
   Tests: `tests/test_live_scorers.mjs`.
