## The pundit-note mystery, solved
The 07-19 handoff said the tally unsealed the whole note archive. It did — briefly.
`scoring_engine.py` doesn't know `stoppage_bet` in its type dispatch, so its blanket
finalize wrote `resolved: False` back onto **all 21 pot rows on every run**, and the
CF-Worker-cron-driven hourly engine passes re-sealed the 17 pot-row notes within
hours. The 07-20 season export is proof: `pot_points` all present, 0/21 resolved.
("Extended bonus bets bumped out the notes" was the visible symptom — sealed notes
render as nothing in the strips.)

Three-part fix, all on disk:
- `scripts/scoring_engine.py` — pot rows (`pot="stoppage"` / type `stoppage_bet`)
  filtered out right after the Predictions fetch; the engine never touches them again.
- `functions/api/[[route]].js` — belt-and-braces: a note unseals if `resolved` OR
  the row is a scored pot row (`pot_points != null`), so the display no longer
  depends on the flag the engine was clobbering.
- `site/live.html` — strips now render a visible "pundit note sealed" placeholder
  when `has_note` && no note (nothing can silently vanish again), and
  `.bstrip .note-line{flex-basis:100%}` gives each note its own row under the
  chips (the old grid-column was a no-op in the flex strip — notes shared a row
  with 5–6 chips on the pot cards).
