## Root causes + fixes (all three share little except they surface at the group→KO transition)

### #1 — Knockout winners never advanced in scoring  →  `scripts/scoring_engine.py`
The engine built `teams_in_match_tier` only from teams that **play in** a round's matches; a KO
`winner` was used solely to set the Champion at the Final. So winning an R32 match never marked a
team "reached R16". Only `"Round of 32"` fixtures exist so far, so Canada's win credited nothing —
every R16-berth bracket pick and the dark-horse ladder stayed 0/unresolved. **This is also why
Andreas's mulligan (R16-1 → Canada) hadn't scored.**
- **Fix:** added `NEXT_REACHED = {"R32":"R16","R16":"QF","QF":"SF","SF":"Final"}` and a pure helper
  `reached_via_winners(finished_ko)`; after the match loop, each finished KO winner is merged into the
  next tier's reached-set (unioned with the existing participation logic). Final winner still handled
  as Champion. Conservative: `tier_complete` only flips a missed pick to resolved once the whole tier
  is decided, so partial R32 results never falsely mark other picks as missed.
- **Proven:** sim with the real data → Canada `team_reached("R16")` True → base 5 → mulligan ×0.5 →
  **+2** (matches the 06-28 handoff). Loser (RSA) not credited; R16 tier not "complete" after 1 result.
- Tests: `tests/test_mulligan_darkhorse.py` 71 → **79**.

### #2 — Mulligan replacements don't surface  →  `site/live.html` (display only)
Slot-keyed renderers (dark horse, bracket chips, teamtags, champion) look up the **bare** slot key,
but a mulligan replacement is a sibling row with key `<slot>|mull` — so they kept showing the original.
- **Fix:** new pure helper `resolveMulligans(list)` collapses each `<slot>|mull` sibling onto its base
  slot (shows the **replacement** team, flags `mulliganed`, keeps `was_team_id`). Routed through
  `indexData` (picksBy), `bracketTiers`, `ladderSets`. Dark-horse card annotated `↺ mull · was XXX`
  (CSS `.mullmark`/`.mullfrom`). Per-category **totals deliberately stay on the raw list** (the engine
  scores both halves), so no double-count.
- **GATE — verify the sibling rows exist before trusting the display.** Counters are at 0 and
  `save_mulligan` spends the mulligan **last** (after writing the sibling + Mulligans link), so they
  almost certainly exist — but I could not read them from here. On the Mac:
  `python3 scripts/mulligan.py --player Cal --list` and `--player Andreas --list`. Expect Cal's dark
  horse to have a `darkhorse|mull` sibling and Andreas an `R16-1|mull` (→ Canada). If a sibling is
  missing, the write didn't complete — re-run the mulligan; the display fix has nothing to show until
  it does.
- Tests: `tests/test_live_alive.mjs` 25 → **39** (incl. resolveMulligans + ladderSets routing).
- Note: bracket **chips** now highlight the replacement team correctly, but only the dark-horse card
  carries the explicit "↺ mull" annotation — adding a bracket-chip badge is an easy follow-up.

### #3 — Third-place teams never marked "out"  →  `site/live.html`
`eliminatedSet()` branch 2 needed `"3rd"` Standings rows; the leaderboards poller only writes those
when the API standings include a "third" table, which API-Football doesn't return for this comp →
**0 such rows** → the 4 non-advancing thirds never struck. (Verified: 12 rank-4 + RSA struck = 13;
should be 16 after groups.) Branches 1 (rank-4) and 3 (KO losers) work.
- **Fix:** when no `"3rd"` rows exist, derive the best-thirds ranking client-side from the 12 group
  tables — sort the twelve rank-3 teams by points, then goal diff, then goals for; eliminate the
  bottom four. Guarded to require ranking data (`points != null`) so it stays conservative if the
  feed lacks it. Explicit-rows path kept as a fallback.
- Tests: covered in `tests/test_live_alive.mjs` (derived-thirds + tie-break + "exactly 16 out").
