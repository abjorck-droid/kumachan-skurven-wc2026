## Root causes + fixes

### #1 — Fixture rows only exist for UTC yesterday+today  →  `scripts/poller.py`
Verified against live `/api/public` (23:57 UTC): only 3 R16 rows existed; **ENG v MEX had no
Matches row at all**. It's the late-US-evening game — kickoff buckets under **July 6 UTC**.
The scoreboard poll queries yesterday+today only, and nothing ever re-runs `load_fixtures.py`,
so next-UTC-day fixtures don't exist → bootstrap has no upcoming matches → bonus tab locks.
Every US evening game (00:00–04:00 UTC bucket) hits this.
- **Fix A:** `poll_dates()` now returns yesterday/today/**tomorrow** (+1 API call per run,
  ~96/day). Rows for next-UTC-day games are created a day ahead.
- **Fix B:** the daily leaderboards run now also refreshes the **full season schedule**
  (1 call/day, same idempotent upsert as `load_fixtures.py`) — KO fixtures exist in Matches as
  soon as API-Football publishes them, giving multi-day bonus windows.
- **Guard:** `to_match_fields()` no longer assumes team objects exist (TBD KO fixtures →
  label "? v ?", no links). Previously `tms["home"].get(...)` would crash on null teams.
- Tests: `tests/test_poller_scoreboard.py` 16 → **27**.
- **Immediate unblock** (told Andreas in-session): `python3 scripts/load_fixtures.py` on the
  Mac creates the missing rows now, before any commit.

### #2 — -soft shades don't follow player colors  →  `site/live.html`
`header()` sets `--p1`/`--p2` from PoolPlayers `display_color` at runtime, but
`--p1-soft`/`--p2-soft` (cell shading) stayed hard-coded blue/orange from the CSS defaults.
Cal is `players[0]` → his cells: orange edge bar (uses `--p1`, correct) + blue shade
(hard-coded, wrong). Not intentional contrast — a plain bug.
- **Fix:** new PURE helper `softColor(hex, alpha)` (hex → rgba); `header()` now sets
  `--p1-soft`/`--p2-soft` from the same player colors (falls back to CSS defaults on bad hex).
  Also `.bk-slot.pboth` and `.ttag.both` gradients switched from hard-coded rgba to the vars.
- Tests: softColor unit tests + CSS wiring checks in `tests/test_live_alive.mjs`.

### #3 — Fit view scale computed from under-reported width  →  `site/live.html`
Columns sum to **1460px** (8×158 + 196 final) but `.bk-bracket` said `min-width:1380px`
(stale from an earlier column width). Flex items overflow the box; `offsetWidth` reports the
box (1380), so Fit scaled by the wrong ratio and `overflow-x:hidden` clipped the right R32
column (~80px).
- **Fix:** `min-width:1460px` (comment explains the invariant) + `bkLayout()` measures
  `Math.max(scrollWidth, offsetWidth)` as a net against future drift. Wires `viewBox`
  deliberately left on offsetWidth (svg renders at box size — 1:1 coords; see comment).
- Tests: static CSS regression in `test_live_alive.mjs` parses column widths + min-width and
  asserts coverage (fails if someone widens columns without bumping min-width).
